СКАН v0.5 — Постоянный общий реестр и вкладки отчётов

УСТАНОВКА
Распакуйте архив. В репозитории SkyAdaLab/scan_prod откройте Code → Add file →
Upload files и перетащите содержимое архива: index.html, app.js, periods.js,
report.js, style.css, папки templates и vendor. Нажмите Commit changes.
UPDATE.txt загружать необязательно. ZIP загружать не нужно.
Старые zxing.min.js и exceljs.min.js в vendor НЕ удаляйте.
config.js и core.js менять не нужно. Архив включает изменения v0.3 и v0.4.
Дождитесь публикации GitHub Pages, обновите приложение. При старом экране:
https://skyadalab.github.io/scan_prod/?v=05
Завершите черновики перед обновлением. На всех устройствах используйте новую версию.

Учёт.xlsx
Первая вкладка ВСЕГДА «Общий реестр». Она содержит всю историю изделий:
номер, наименование, дату поступления, дату выбытия, статус и ссылку на фото.
Завершённые выбытия помечаются красным. Ожидающие фото — жёлтым.
Новые поступления добавляются в общий реестр. При выбытии строка обновляется,
а не удаляется. Если изделие возвращается, его новое поступление создаёт
отдельную запись, сохраняя предыдущую историю.

Кнопка «Отчёт» создаёт дополнительную вкладку с датой, например «12.11.2026».
В ней только выбывшие изделия, вошедшие в этот акт, без цветной заливки.
Общий реестр при этом остаётся первым, все записи остаются в нём.
Следующий отчёт включает только новые завершённые выбытия; предыдущие вкладки
отчётов не дополняются. За один день: «12.11.2026», «12.11.2026 (2)» и далее.
Вкладки «Текущие» больше нет.
Если изделие поступило до прошлого отчёта, а выбыло после него, оно всё равно
попадёт в следующий отчёт. Его строка в общем реестре станет красной.

ОДС-АКТЫ
Название: АКТ_передачи_на_ремучасток_.ods
Путь: папка учёта / Отчёты / дата отчёта / АКТ_передачи_на_ремучасток_.ods
Дата — с телефона при начале формирования. Формат и шаблон прежние.
Предыдущие акты сохраняются в своих папках. Если новых выбытий нет,
дополнительная вкладка и акт не создаются.
Перед отчётом завершите все черновики и загрузку фотографий.
При сбое сохранения нажмите «Отчёт» / «Повторить формирование».
Новые сканы доступны после завершения сохранения отчёта.

ПЕРЕХОД С v0.4
Все исходные записи остаются в папке «Данные» и используются для восстановления
полного общего реестра. При следующем сохранении операции или отчёта Учёт.xlsx
будет собран в новом виде: общий реестр первым, затем отчёты по датам.
Существующие периоды сохраняются; в датированных вкладках теперь только
изделия из соответствующих актов, а не все операции периода.
Не удаляйте служебный файл «Периоды.json» и папку «Данные».

Если версия v0.4 ещё не использовалась, первый отчёт зафиксирует накопленные
выбытия. Старые границы отчётов v0.3 автоматически восстановить нельзя,
так как они не сохранялись. Последующие отчёты включают только новые выбытия.

ПРОВЕРКА
1. Новый → наименование → уникальный номер → Продолжить.
2. Выбыл → тот же номер → фотографии → Сохранить.
3. Отчёт → дождитесь подтверждения.
4. Откройте Учёт.xlsx: первая вкладка — общий реестр, выбытие красное.
   Следующая вкладка с датой содержит только изделия из акта.
5. Закройте редактирование Excel на компьютере. Добавьте ещё одно изделие.
   Оно появится в общем реестре; предыдущая вкладка отчёта не изменится.

Одновременная запись с нескольких устройств на один Диск не поддерживается:
работайте по очереди. Закрывайте редактирование таблицы на компьютере перед
отправкой с телефона, чтобы Яндекс не блокировал файл (HTTP 423).
Ограничение тестовой версии на 500 файлов операций снято. При росте истории
загрузка может занимать больше времени, так как приложение читает все операции.

Проверено автоматическим созданием и повторным чтением Excel: порядок листов,
сохранение всех записей, красные выбытия, неизменность отчётных вкладок,
отсутствие повторов, несколько отчётов за день, выбытие старого поступления.
Живая запись на ваш личный Яндекс Диск из этой среды не выполнялась.
