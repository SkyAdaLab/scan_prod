СКАН v0.6 — Очередь и отправка пачкой

УСТАНОВКА ПОВЕРХ СУЩЕСТВУЮЩЕГО ПРИЛОЖЕНИЯ
1. Завершите старые черновики. Распакуйте ZIP на компьютере.
2. В репозитории scan_prod: Code → Add file → Upload files.
3. Перетащите содержимое архива: index.html, app.js, batch.js, periods.js,
   report.js, style.css, папки templates и vendor. Подтвердите Commit changes.
   ZIP и UPDATE.txt загружать не нужно. Загружайте файлы в корень репозитория.
4. НЕ удаляйте существующие config.js, core.js и библиотеки в vendor.
   Новые файлы заменяют одноимённые, остальные остаются.
5. Дождитесь завершения публикации Pages. Откройте на телефоне:
   https://skyadalab.github.io/scan_prod/?v=06
   На всех используемых устройствах обновите страницу.

КАК РАБОТАТЬ
Новый → наименование → сканируйте подряд. Камера запускается автоматически
и остаётся включённой при добавлении поступлений. Успешное добавление
подтверждается звуком, если браузер разрешает воспроизведение.
Наименование выбирается один раз для серии; есть кнопка его изменения.
Ручной ввод сохранён: «Ввести номер вручную» → «Добавить».
Один удерживаемый перед камерой код не добавляется многократно.

Выбыл → номер камерой или вручную → фото номера и общий план обязательны,
средний план по желанию → «В очередь и следующий скан».
Сканер снова открывается для следующего изделия.

Очередь / отправить всё → проверьте список → «Отправить всё».
Записи и фотографии загружаются последовательно, Excel обновляется ОДИН РАЗ
в конце попытки отправки. До отправки новые позиции находятся только
в браузере телефона. Загрузка фотографий всё равно требует времени.
Не закрывайте страницу во время отправки.

Очередь сохраняется при перезагрузке страницы. После подключения того же
аккаунта в том же браузере её можно продолжить. Не очищайте данные сайта
и не используйте приватный режим для длительного хранения очереди.
При сбое повторите отправку: уже записанные операции не дублируются,
подтверждённые фотографии не загружаются заново. Если сбой произошёл только
на Excel, повтор завершит обновление таблицы.
Можно удалять ещё не отправленные позиции. Начатые отправки нужно завершить
повтором. При поступлении и выбытии одного номера в очереди сначала удаляется
выбытие, потом поступление.

РЕЕСТР И ОТЧЁТ
Основной общий реестр остаётся первой вкладкой, выбытия отмечаются красным.
Отчёт сохраняет прежний шаблон АКТ_передачи_на_ремучасток_.ods и создаёт
отдельную вкладку с датой. Перед формированием отчёта отправьте всю очередь.
Существующие Данные и Периоды.json не удаляйте.

ПРОВЕРКА НА ТЕЛЕФОНЕ
1. Новый → наименование → введите вручную два разных тестовых номера.
2. Повтор первого номера должен отклоняться.
3. Перезагрузите страницу и подключитесь: обе позиции должны остаться.
4. Откройте очередь → Отправить всё. Проверьте обе строки в Учёт.xlsx.
5. Закройте таблицу на компьютере. Выбыл → один из номеров → два фото →
   В очередь и следующий скан. Убедитесь, что снова появился сканер.
6. Отправьте очередь, проверьте красную строку и фотографии на Диске.
7. Сформируйте отчёт: только завершённое выбытие попадёт в акт.

Работайте с одним Диском на одном устройстве одновременно. Перед отправкой
закрывайте редактирование Excel на компьютере: оно может блокировать файл
(HTTP 423). При этой ошибке очередь остаётся для повторной отправки.

Проверены ручной ввод, запрет дублей, восстановление очереди и её обработка
в демонстрационном режиме браузера, а также сценарии повторной отправки
в программных тестах. Реальная камера и запись на личный Яндекс Диск
требуют проверки на вашем телефоне.
